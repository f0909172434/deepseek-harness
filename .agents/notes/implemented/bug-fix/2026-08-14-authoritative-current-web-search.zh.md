# Agent Note：权威的当前 Web 搜索

Status: implemented

[English](2026-08-14-authoritative-current-web-search.md) | 中文

## Problem

针对当前、最新和截至某日的问题，即使 `web_search` 成功运行，也可能生成陈旧比较。面向模型的工具只接受查询，因此调用方无法要求仅第一方来源的验证轮次。已发布的 DeepSeek 提供方还通过独立的辅助 Messages 请求执行搜索；该请求不会继承外层 agent（智能体）的 system prompt（系统提示词）或时间上下文。之前的一行指令既不保留明确的时间意图，也不要求核验当前版本和生成引文摘录。在仅搜索的组合中，外层 agent 经常只收到标题和 URL，因此可能把排名靠前的旧项目误认成当前产品或基准条目。

## Decision

`web_search` 现在接受可选的 `allowed_domains`，并在 seam（接缝）中映射为 `allowedDomains`。可移植契约有意限定为 1–20 个仅含可打印 ASCII 的裸主机名。seam 在提供方发出请求前将列表转为小写并去重，拒绝 scheme（协议）、路径、端口、凭据、通配符和 IP 字面量，并允许精确主机及其子域名。Exa 接收 `includeDomains`，Perplexity 接收 `search_domain_filter`，DeepSeek 的 Anthropic 兼容原生搜索工具接收 `allowed_domains`。

系统不把提供方侧控制当作后置条件。提供方返回后，seam 会先根据规范化允许列表核验每一个结构化来源 URL，再应用 `maxResults`。任何违规都会以 `WEB_SEARCH_FILTER_VIOLATION` 失败；无效输入则以 `WEB_INVALID_SEARCH_FILTER` 失败。错误消息只标识来源位置，绝不回显提供方 URL，因为返回的查询字符串可能包含敏感值。系统不会机械解析提供方生成的正文，因此保证有意仅限于结构化来源。

模型指引现在要求对可变的当前、最新和截至某日声明执行搜索，要求在查询中加入绝对日期，建议先进行带第一方允许列表的轮次，再进行不受限的独立比较轮次，禁止在无法解析当前版本时以旧版本替代，并要求模型披露缺失的摘录。独立的 DeepSeek 辅助请求会重复时间与来源权威性策略，并要求引文，以便引文摘录可以填充规范化的 snippet（摘要片段）。

## Alternatives considered

**把时间上下文组合变更视为完整修复。** 拒绝。时间上下文会到达外层对话，而 DeepSeek 原生搜索是在独立 Messages 请求中规划的。额外的搜索轮次需要自己的明确指令，而且仅有时间并不能提供第一方检索控制。

**同时加入新近性、日期范围、排名和来源策略字段。** 本次变更拒绝这样做。当前提供方对这些控制没有共同且诚实的硬语义，而 DeepSeek 的 `page_age` 是提供方给出的标签，并非可比较的 ISO 时间戳。提升不受支持的字段会暗示 seam 无法执行的保证。

**在已发布组合中启用 `web_fetch`。** 拒绝。在完成私有网络保护和每次重定向跳转保护之前，已发布的 fetch 提供方保持禁用；新近性修复不能重新打开已知的 SSRF 边界。

**静默丢弃允许列表之外的来源。** 拒绝。提供方生成的答案可能已经依赖被丢弃的来源，静默过滤会把混合范围的证据伪装成已通过验证。明确失败可保留可审计的边界。

## Consequences

调用方现在无需新增提供方专属工具，即可进行确定性的第一方结构化来源轮次。允许列表可移植且经 seam 核验，但它不是新近性过滤器，也不能证明提供方生成的正文只使用了允许的证据。当前性仍取决于含绝对日期的查询、证据完整性和回答模型的综合。

提示词变更会缓解陈旧查询规划和缺失引文摘录的问题，但不能保证上游搜索索引包含最新页面，也不能保证其原生排名在时间上正确。缺失的当前版本必须保持明确，不得用旧版本填补。除此之外，搜索结果顺序仍由提供方拥有；`publishedAt` 仍是不透明的提供方日期或页面年龄标签，在没有另一个规范化契约之前，不得用于跨提供方的时间排名。
